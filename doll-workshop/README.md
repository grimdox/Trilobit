# Trilobit Doll Workshop

A standalone, data-driven Godot project for Trilobit's characters: six body frames (male and female, small, medium,
large), recolourable skin, hair and eyes, 14 hair styles, 5 eye shapes in 6 expressions, 43 garments and 22 outfit presets, 22 implants
on every body part, an android variant, and every gun, blade and tool of the game held in six stances, with idle,
walk, action, hit and fall animations.  Everything is generated by code from data and baked into atlases that a small
runtime draws with one palette shader.

| | |
|---|---|
| Engine | Godot **4.5.2-stable**, standard build, **Compatibility** renderer (see [docs/TOOLCHAIN.md](docs/TOOLCHAIN.md) for why not .NET here) |
| Runtime | `addons/trilobit_doll/` (GDScript; also runs in the game's Godot 4.3) |
| Generator | `tools/dollgen/` (Python 3 + numpy, scipy, Pillow; a small C core compiled on first use) |
| Baked sets | `dolls/` (64 px, for close-ups, creation and UI) and `dolls32/` (32 px world set for the map), same format and ids |
| Tests | `bash run_all.sh` |

## Quick start

```sh
# bake (about 25 min on 2 cores for 64 px, 8 for 32 px; --bodies m_m --frames 20 for a quick test)
python3 tools/dollgen/bake.py ../godot-spike/data/items.json dolls --jobs 2
python3 tools/dollgen/bake.py ../godot-spike/data/items.json dolls32 --jobs 2 --lod 32
# check it
bash run_all.sh
# open the workshop
godot --path .
```

In the game (or any project): copy `addons/trilobit_doll/` and `dolls/`, then

```gdscript
const RIG = preload("res://addons/trilobit_doll/doll_rig.gd")
var doll = RIG.new()
add_child(doll)
doll.scale_px = 2                       # whole numbers keep pixels crisp
doll.set_spec({"body": "f_m", "hair": "bob", "garments": ["under", "bodysuit", "boots_high"],
               "colours": {"skin": "porcelain", "hair": "violet black"}, "item": "trl_gun_sp45"})
doll.play("walk")
doll.anim_event.connect(func(a): print("shot fired"))     # the action's strike / fire frame
```

On the map, use the world set: `doll.library_path = "res://dolls32"` before adding it (or `set_library(...)`).  The game
now draws 64 px sprites shrunk into 27 px tiles; the 32 px set is rendered natively at half scale with its own faces,
and reads far better at that size (see the game-scale sheet).

From the game's current look data: `trilobit_adapter.gd` `spec_from_game(layers, look, weapon)`.
Random characters: `doll_generator.gd` `generate(seed, archetype)` - deterministic, rule-checked, every repair logged.

## The pipeline in one paragraph

A body frame is a set of proportions on one skeleton; a pose is a set of targets (hands on a weapon's grip and haft,
feet on the ground) solved with two-bone IK.  The body is built from anatomical solids (rib cage, pectorals, deltoids,
biceps, quadriceps, calves, ...) smooth-joined along the skeleton (hand into forearm, arm into torso), so shoulders
and hips grow out of the torso but a raised arm never webs to the jaw, and ray-marched in 3D at three samples per pixel.  The pixel pipeline then takes over: each pixel takes one surface (no blending), light comes
from one key with a face fill, occlusion darkens real creases, the value is cut into five shades on a hand-built ramp,
a cyan rim catches the shadow side, stray pixels and notches are repaired (counted per frame in the manifest), a handful of deliberate anatomical
marks (pectoral line, abdominals, collarbones, deltoid split) are painted on the surface, and each layer gets a 1 px
ink outline that skips smooth joins.  Garments and implants are inflated copies of the same solids, so they fit every
body in every pose; faces are hand-designed pixel stamps.  Every pixel is stored as material x 8 + shade, so the
runtime recolours skin, hair, eyes, cloth, metal and lights with a palette per character.
